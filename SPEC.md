# Спецификация: приложение-сайт по метакогнитивной терапии (протокол Уэллса для ГТР)

**date-create:** 2026-10-24 17:45
**Версия:** 0.2
**Статус:** черновик для старта разработки

---

## 1. Цель

Личное веб-приложение (один пользователь, без регистрации), которое ведёт по 10-этапному протоколу метакогнитивной терапии (MCT, Adrian Wells) при генерализованном тревожном расстройстве (ГТР): показывает текущий этап и задания, хранит дневник и эксперименты, отслеживает оценки метаубеждений и шкалу GAD-7, присылает напоминания, использует GPT через API как «ассистента терапевта» для концептуализации и разбора экспериментов.

Главная метрика приложения — снижение оценок метаубеждений (в процентах) по трём группам: неконтролируемость, опасность, польза беспокойства.

## 2. Ограничения и принципы

- Один пользователь, регистрации нет. Приложение работает на main-сервере (раздел 12) и закрыто паролем; требования к безопасности — раздел 13.
- Все данные (дневник, убеждения, эксперименты, диалоги, оценки) хранятся только на своём сервере, база зашифрована (раздел 13).
- Все тексты этапов, заданий и промптов — **в своих словах**. Не копировать текст из книг Уэллса и Каллесен. Книги используются только как источник структуры метода.
- Тексты и промпты лежат в отдельных файлах (`content/`), а не в коде, чтобы их можно было править без правки приложения.
- Секреты (ключи OpenAI и Gemini, секрет пересылки Gemini, токен Telegram, ключ шифрования базы, хеш пароля входа) — только в `.env`, файл в `.gitignore`.
- Интерфейс на русском языке.
- Простота важнее масштабируемости: один процесс, одна база.

## 3. Стек (предложение, можно изменить при старте)

- **SvelteKit** (Node.js) — фронтенд и серверные маршруты в одном проекте.
- **SQLite** через `better-sqlite3-multiple-ciphers` — тот же интерфейс, что у `better-sqlite3`, плюс шифрование всего файла базы (SQLCipher). Одна база в файле `data/app.db`.
- **GPT и Gemini — напрямую из серверной части приложения** (раздел 12.2), ответы в JSON. Ключи никогда не попадают в браузер.
- **n8n** (уже есть у пользователя, self-hosted) — расписания напоминаний, отправка в Telegram. Приложение отдаёт данные для напоминаний через свой HTTP API.
- Разработка: `npm run dev` в WSL. Работа: main-сервер, `pm2` или systemd, снаружи — через nginx (раздел 12.1).

## 4. Модель данных

Описание таблиц. Точные типы и индексы — на усмотрение разработчика.

### 4.1 `profile` (одна строка)
- `started_at` — дата старта.
- `current_stage` — номер текущего этапа (1–10), после 10 — режим поддержки (`11`).
- `reminder_worry_window` — время вечернего окна для беспокойства (например `18:00`).
- `reminder_att` — время тренировки внимания (ATT), может быть пусто.
- `reminder_weekly_review` — день и время еженедельного обзора.
- `telegram_chat_id` — для n8n.

### 4.2 `beliefs` (метаубеждения)
- `id`
- `type` — одно из: `uncontrollability` (неконтролируемость), `danger` (опасность), `usefulness` (польза).
- `text` — формулировка своими словами («если я начну беспокоиться, то не смогу остановиться»).
- `created_at`, `archived_at`.

### 4.3 `belief_ratings` (история оценок)
- `belief_id`, `rated_at`, `percent` (0–100), `context` — `weekly` / `after_experiment` / `initial`.

### 4.4 `formulation` (концептуализация, одна строка, редактируемая)
- `trigger_examples` — типичные триггеры.
- `worry_chain` — как разворачивается беспокойство (тип 1).
- `type2_worry` — беспокойство о беспокойстве.
- `coping_strategies` — что человек делает: подавление, поиск успокоения, избегание, отвлечение и т.д. (список с отметками).
- `raw_dialog` — сохранённый диалог с GPT, из которого это получено.
- `updated_at`.

### 4.5 `journal_entries` (дневник, универсальная запись)
- `id`, `created_at`, `stage` (номер этапа, на котором сделана запись).
- `kind` — одно из:
  - `trigger` — заметил триггер; поля: `postponed` (отложил ли), `note`.
  - `worry_window` — вечернее окно; поля: `wanted_to_worry` (захотелось ли беспокоиться), `minutes_used`, `note`.
  - `type2` — эпизод беспокойства о беспокойстве; поля: `note`.
  - `att` — выполнил тренировку внимания; поля: `minutes`.
  - `free` — свободная запись.
- `payload` — JSON с полями, зависящими от `kind`.

### 4.6 `experiments` (поведенческие эксперименты)
- `id`, `stage`, `belief_id`.
- `kind` — `amplify_release` (усилить / отпустить), `lose_control` (попробовать потерять контроль), `day_with_without` (день с беспокойством / без), `stop_reassurance` (отказ от поиска успокоения), `custom`.
- `prediction` — что, по мнению пользователя, случится.
- `prediction_percent` — уверенность в прогнозе.
- `what_i_did`, `what_happened`.
- `conclusion` — вывод, пишет сам пользователь.
- `belief_before_percent`, `belief_after_percent`.
- `gpt_questions` — вопросы GPT к результату (JSON).
- `created_at`, `completed_at`.

### 4.7 `scales`
- `id`, `kind` (`gad7`), `taken_at`, `answers` (JSON из 7 чисел 0–3), `total`.

### 4.8 `stages` — справочник, **не в базе**, а в `content/stages/NN.md` + `content/stages.json`
Для каждого этапа:
- `number`, `title`, `goal` — цель этапа одной фразой.
- `description` — объяснение для пользователя (markdown).
- `tasks` — список заданий на этап.
- `journal_kinds_enabled` — какие типы записей доступны.
- `experiments_enabled` — какие эксперименты доступны.
- `unlock_rule` — условия открытия следующего этапа: `min_days`, `min_entries` (с указанием `kind`), `min_experiments`, `belief_threshold` (тип убеждения и максимальный процент).

## 5. Маршрут этапов (содержание для `content/stages`)

| № | Тема | Что делает пользователь | Условие перехода |
|---|------|------------------------|------------------|
| 1 | Модель и концептуализация | Диалог с GPT по шаблону, заполнение `formulation`, выписывание убеждений с процентами, первая GAD-7 | Концептуализация заполнена, есть минимум по 1 убеждению каждого типа |
| 2 | Отстранённая осознанность + откладывание беспокойства | Записи `trigger`, `worry_window`, `type2` | 7 дней, 10+ записей `trigger` |
| 3 | Неконтролируемость, часть 1 | Эксперимент `amplify_release`, продолжение откладывания | 1+ завершённый эксперимент |
| 4 | Неконтролируемость, часть 2 | Отказ от подавления мыслей, повтор эксперимента, переоценка убеждений | Оценка `uncontrollability` ниже 50% |
| 5 | Опасность, часть 1 | Разбор убеждений об опасности, эксперимент `lose_control` | 1+ эксперимент |
| 6 | Опасность, часть 2 | `stop_reassurance`, переоценка | Оценка `danger` ниже 50% |
| 7 | Польза, часть 1 | Вопросы к пользе (GPT), эксперимент `day_with_without` | 1+ эксперимент |
| 8 | Польза, часть 2 | Переоценка, стратегический отказ от беспокойства | Оценка `usefulness` ниже 50% |
| 9 | Закрепление | Письменный план действий на триггер (новое поле в `profile` или отдельная таблица `plans`) | План написан |
| 10 | Профилактика рецидива | Обзор графиков, итоговая схема «старый способ / новый способ» | Еженедельная GAD-7 ниже 10 две недели подряд |
| 11 | Поддержка | Еженедельная GAD-7, напоминание о плане | — |

Переход между этапами: приложение проверяет `unlock_rule` и показывает «можно перейти» / «пока нет и почему». Кнопка перехода нажимается вручную. Есть принудительный переход с пометкой «вручную» (для отладки и гибкости).

## 6. Экраны

1. **Сегодня** — текущий этап, его цель, задания, быстрые кнопки: «заметил триггер», «вечернее окно», «тип-2», «ATT». Ближайшие напоминания.
2. **Этап** — полное описание этапа, прогресс по условиям перехода, кнопка перехода.
3. **Дневник** — лента записей с фильтром по типу и этапу, добавление записи.
4. **Эксперименты** — список, создание (прогноз до), завершение (результат, вопросы GPT, вывод, оценка после).
5. **Убеждения** — список по трём группам, текущие проценты, графики истории, еженедельная переоценка.
6. **Шкалы** — GAD-7, график по неделям.
7. **Обзор недели** — сводка GPT по записям, рекомендация по переходу.
8. **Настройки** — времена напоминаний, Telegram chat id, экспорт данных в JSON.

## 7. Интеграция с GPT

Все вызовы — с сервера, напрямую в OpenAI или Gemini (раздел 12.2). Модель выбирается переключателем на экране разговора; у каждого ответа сохраняется, какая модель его дала и за сколько секунд. Промпты в `content/prompts/*.md`. Ответы просить в JSON по заданной схеме.

1. **Концептуализация (этап 1).** Диалог: GPT задаёт вопросы по одному (недавний эпизод беспокойства, что думал о самом беспокойстве, что делал, чтобы справиться, зачем беспокойство нужно, чего боится в беспокойстве). По завершении возвращает JSON: `formulation` и список `beliefs` с типом и формулировкой. Пользователь проверяет и правит перед сохранением.
2. **Разбор эксперимента.** Вход: убеждение, прогноз, результат. Выход: 2–4 вопроса в сократовском стиле. GPT **не пишет вывод** — вывод пишет пользователь.
3. **Еженедельный обзор.** Вход: записи за неделю, оценки, GAD-7, текущий этап и его `unlock_rule`. Выход: краткая сводка (где ещё вовлекается в беспокойство, что получается), готовность к переходу `ready: true/false` с причиной.
4. **Вопросы к пользе (этап 7).** Вход: убеждения типа `usefulness`. Выход: список вопросов для самопроверки.

Правило для всех промптов: GPT не ставит диагнозы, не даёт медицинских советов, не заменяет вывод пользователя своим. Ответы на русском.

## 8. Напоминания (n8n)

Приложение отдаёт эндпоинт `GET /api/reminders` с ответом: текущий этап, какие напоминания активны и во сколько, `telegram_chat_id`, ссылки на нужные формы.

n8n: три расписания (вечернее окно, ATT, еженедельный обзор). Каждое — запрос к `/api/reminders`, проверка, актуально ли напоминание для текущего этапа, отправка в Telegram сообщения с кнопкой-ссылкой.

Эндпоинт защищён простым токеном в заголовке (значение в `.env`).

## 12. Сервер и голосовой диалог с аватаром

### 12.1 Размещение
- Приложение работает на main-сервере пользователя: Ubuntu 24.04, 4 ядра, 7,7 ГБ памяти, видеокарты нет. На 2026-11-23 свободно около 5 ГБ памяти и 11 ГБ диска (диск занят на 87%).
- Это заменяет вариант «localhost» из раздела 2 и закрывает первый вопрос раздела 11.
- Доступ снаружи — только по HTTPS через nginx и вход по паролю (раздел 13). Без защиты приложение наружу не открывается.
- Запуск — `pm2` или systemd. Деплой — `rsync -avz --delete`, перед первым прогоном — `--dry-run`.
- При деплое не перезаписываются: база `data/app.db`, модели речи `models/`, файл `.env` (исключены из rsync).
- Резервная копия базы — ежедневно; способ выбрать при настройке сервера.

### 12.2 GPT
- **Модели — напрямую, без n8n** (исключение из общего правила пользователя «GPT только через n8n», согласовано 2026-11-25). Причины: тексты разговора не должны оседать открытым текстом в истории n8n; ответ можно получать по частям (аватар начинает говорить раньше); на одно звено меньше. Правило про n8n касается домашнего IP, а приложение работает на main — том же сервере, откуда n8n ходит в OpenAI.
- OpenAI — напрямую с main. Gemini — через пересылку на сервере mvps (Google блокирует main по стране), как у n8n.
- Ключи — отдельные для этого приложения, с лимитом расходов; вносит их пользователь сам (`scripts/set-secret.js`), в `.env` на сервере. Ключи других проектов не переносятся.
- Gemini — только платный тариф (на бесплатном Google может использовать запросы для обучения).
- Токен шлюза — только в `.env` на сервере.
- Модели выбраны сравнением на одном тестовом разговоре (2026-11-26): по умолчанию Gemini 3.6 Flash (~1,7 с на ответ, лучшее качество разговора); ещё Gemini 3.8 Flash, GPT-6 Luna (самая дешёвая, ~2,3 с), GPT-5.6 Luna, GPT-6.1 Terra. Цена разговора — доли цента. Gemini 2.5 Google отключает 2026-12-01; GPT-5, GPT-5 mini, GPT-4.1 показали себя хуже.
- У пересылки на mvps свой пароль для приложения (`/etc/nginx/gemini-relay-mct.keys`), отдельный от пароля n8n.

### 12.3 Голосовой диалог
Цель — разговаривать с приложением голосом в сценариях раздела 7, прежде всего в диалоге концептуализации (этап 1). Текстовый режим остаётся всегда.

Одна реплика проходит так:
1. Браузер записывает голос по кнопке «нажми и говори». Постоянного прослушивания нет.
2. Аудио отправляется на свой сервер.
3. Сервер распознаёт речь локально: faster-whisper, модель `small` (если медленно — `base`), на процессоре.
4. Распознанный текст появляется в чате; при ошибке его можно исправить и отправить заново.
5. Сервер отправляет текст в выбранную модель (GPT или Gemini) и получает ответ.
6. Сервер синтезирует голос локально: Silero TTS (русский голос), запасной вариант — Piper.
7. Браузер проигрывает голос, аватар двигает губами в такт; текст ответа тоже показывается.

Приватность:
- Аудио не покидает свой сервер. Наружу уходит только текст реплик в GPT — как и в текстовом режиме.
- Встроенное распознавание речи браузера (Web Speech API) не использовать: Chrome отправляет звук в Google.
- HeyGen и другие облачные аватары не используются.
- Аудиофайлы удаляются сразу после распознавания; хранится только текст диалога (`raw_dialog`).

### 12.4 Аватар
- 3D-аватар отрисовывается в браузере (Three.js; основа — открытая библиотека вроде TalkingHead или модель формата VRM). Сервер только отдаёт файлы модели.
- Губы двигаются по звуку ответа; плюс моргание и простые состояния «слушает» и «думает».
- Модель аватара — с лицензией, разрешающей такое использование; конкретную выбрать при реализации.
- Должен работать в мобильном браузере. Есть переключатель режимов: «аватар», «только голос», «только текст».
- Фотореалистичные локальные аватары (MuseTalk, LivePortrait и подобные) не используются: им нужна видеокарта, а на main-сервере её нет.

### 12.5 Ресурсы и ожидания
- faster-whisper `small`: около 1 ГБ памяти, ожидаемо несколько секунд на фразу на 4 ядрах — проверить замером.
- Silero TTS: около 0,5 ГБ памяти, около секунды на ответ.
- Цель: от конца фразы до начала ответа — не больше ~8 секунд. Если дольше — модель `base` или озвучка ответа по частям.
- Модели занимают ~1–1,5 ГБ диска; перед установкой проверить свободное место.
- Пользователь один, реплики распознаются по одной (простая очередь).

### 12.6 Место в фазах
- Фаза 1: приложение сразу разворачивается на main-сервере (12.1), голоса нет.
- Фаза 2: прямое обращение к GPT/Gemini (12.2), текстовый диалог концептуализации, переключатель модели.
  Сделано: экран «Разговор» (`/talk`), таблицы `conversations` и `conversation_messages` (миграция 002), промпт `content/prompts/conceptualization.md`, у каждого ответа — модель и время. Черновик схемы и убеждений проверяется и сохраняется пользователем; при сохранении диалог пишется в `formulation.raw_dialog`. Можно включить озвучку ответов голосом Silero с 2D-аватаром.
- Фаза 2а (после приёмки Фазы 2): распознавание и синтез речи на сервере, голосовой режим без аватара.
- Фаза 2б: 3D-аватар поверх голосового режима.

## 13. Безопасность и шифрование

Приложение хранит очень личные данные, поэтому ниже — обязательный минимум. Он входит в Фазу 1: без него приложение наружу не открывается.

### 13.1 Доступ
- Только HTTPS (сертификат Let's Encrypt в nginx), запросы по HTTP перенаправляются на HTTPS, включён HSTS.
- Приложение слушает только `127.0.0.1`, снаружи доступно только через nginx.
- Вход — своя страница с паролем. В `.env` хранится не пароль, а его хеш (scrypt — встроен в Node, без внешних библиотек).
- После входа — сессия в cookie с флагами `HttpOnly`, `Secure`, `SameSite=Lax`, срок 30 дней; есть кнопка «Выйти». `Lax`, а не `Strict`: иначе ссылки из Telegram-напоминаний открывали бы страницу входа. От подделки форм защищает проверка источника запроса в SvelteKit.
- Защита от подбора пароля: не больше 5 попыток в минуту, после 10 неудач подряд — пауза 15 минут.
- Без входа доступны только страница входа и `/api/reminders` (по токену из раздела 8). n8n стоит на том же сервере и обращается к приложению напрямую через `127.0.0.1`.
- Заголовки безопасности: Content-Security-Policy, запрет встраивания в чужие страницы (`frame-ancestors 'none'`), `Referrer-Policy: same-origin` (не `no-referrer`: с ним браузер отправляет формы с `Origin: null`, и они отклоняются как чужие).
- В логи (приложения и nginx) не попадает содержимое записей, диалогов и паролей — только служебная информация.

### 13.2 Шифрование
- **При передаче:** телефон ↔ сервер — HTTPS; сервер ↔ OpenAI / пересылка Gemini — HTTPS.
- **При хранении:** весь файл базы зашифрован (SQLCipher, AES-256, через `better-sqlite3-multiple-ciphers`). Без ключа файл не прочитать: это защищает от утечки самого файла, копии или резервной копии.
- Ключ шифрования — длинная случайная строка в `.env` на сервере (права `600`, владелец — пользователь, от которого работает приложение). В репозиторий ключ не попадает.
- Резервные копии делаются из зашифрованной базы и остаются зашифрованными. Копия ключа хранится отдельно от копий базы (например, в менеджере паролей). **Потеря ключа = потеря всех данных.**
- Аудио не хранится (раздел 12.3).
- Экспорт в JSON (Фаза 3) — только после входа, файл скачивается на устройство пользователя.

### 13.3 Что эта защита не закрывает
- Ключ лежит на том же сервере, что и база: тот, кто получит полный доступ к серверу, сможет прочитать данные.
- Усиленный вариант (решить позже): ключ выводится из пароля входа и хранится только в памяти; после перезапуска приложение заблокировано, пока не войдёшь. Минусы: напоминания, которым нужны данные, не работают до входа, а забытый пароль = потерянные данные.
- Текст реплик, отправляемых в модель, видят OpenAI или Google (и сервер пересылки mvps — без сохранения). Поэтому:
  - в GPT отправлять только то, что нужно для конкретного вызова, без имён и контактов;
  - в журналы приложения и пересылки текст запросов не пишется.
